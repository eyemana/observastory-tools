# Observastory 1.0 beta content model

This document is the product contract for note eligibility, authored claims, embeds, and `Inline Embed References...`.

## Managed content roots

Managed content roots are the project folders and explicit entity paths declared by Observastory configuration. They normally include Scenes, Characters, Narrators, Plot Threads, Arcs, Story Engines, and Notes, but a project may rename, remove, or add roots.

Managed content roots define the default scope of content-management commands. They are deliberately narrower than the entire vault so archive, research, export, and unrelated folders are not rewritten without specific author approval.

## Note eligibility

`type: scene` is the sole ordinary unit of scene evaluation.

- A Markdown note under the configured Scenes root is an independent scene only when its frontmatter contains `type: scene`.
- An untyped note under Scenes is free-writing or composition material. It is not independently evaluated, queued, ordered, inferred as manuscript truth, or indexed for authored `[!claim]` callouts.
- Notes under other configured roots participate according to that root's entity configuration and filters. They do not acquire a general `type` requirement merely because scene notes have one.
- Notes outside managed content roots are outside Observastory processing unless a command explicitly includes them.

An untyped scene-folder note may be embedded by a registered scene. Its prose then participates through that scene's effective content; the untyped note does not become an independent source.

## Claims

`[!claim]` callouts may be authored in any managed note, including registered scenes and configured character, narrator, plot-thread, arc, story-engine, and notes content.

An untyped note under Scenes is the exception: claims in it are invisible on their own. If its content is embedded by a registered scene, those claims participate through the registered scene's effective content.

The same authored claim may intentionally occur in several managed notes. The Truth Ledger should consolidate equivalent claims while retaining every source occurrence. Repetition can express relevance or emphasis. Reusing an ID with conflicting claim content should be reported as a conflict that needs author attention, not rejected merely because the ID appears more than once.

## Embeds

Obsidian embeds may occur in any note, typed or untyped.

Registered scenes expand prose embeds transiently for evaluation. Whole-note, heading, and block embeds are supported by the current scene-composition engine. Shared embeds remain supported: an author may intentionally keep one source embedded by several destinations for as long as that workflow remains useful.

An embed can also serve as temporary composition material. The source remains canonical until the author explicitly chooses to inline it. Evaluation does not require inlining, warn merely because an embed remains shared, or rewrite authored notes.

## `Inline Embed References...`

This command is a general managed-content utility, not a scene-only normalization command.

The selection list presents unique embedded source notes found from references in managed content. Each source may show its distinct whole-note, heading, and block selectors and occurrence counts. The source note is the unit of selection: all chosen references resolving to that source are handled together so the source can be removed coherently.

### Preflight

The command performs no writes before confirmation.

1. Resolve the selected source and discover every matching embed occurrence inside managed content roots.
2. Discover matching occurrences outside managed roots.
3. Resolve every whole-note, heading, and block selector in memory and verify that each selected replacement can be produced.
4. Present one impact summary listing the source to be removed, in-scope destination notes and occurrence counts, any unresolved references, and every out-of-scope occurrence.
5. Offer **Cancel** before any note is changed. The author may instead continue with managed references only or explicitly include selected out-of-scope occurrences.

Continuing with managed references only may deliberately leave hanging embeds in unconfigured notes. The confirmation must say so plainly.

### Confirmed transaction

After confirmation:

1. Replace each chosen embed occurrence with the content selected by that occurrence. Whole-note, heading, and block embeds may therefore materialize different portions of the same source.
2. Preserve unrelated content and frontmatter in every destination note.
3. Complete all destination writes successfully.
4. Move the obsolete source note to the user's configured Obsidian trash only after the destination writes succeed.
5. Report every modified destination and any intentionally unprocessed out-of-scope reference.

Inlining fans content out to every chosen destination. The resulting passages are intentional independent copies: they begin from the same source but may subsequently diverge in their own contexts.

The POC expands embeds transiently for registered scene evaluation. Other configured note types retain ordinary Obsidian embed behavior, while `Inline Embed References...` can materialize their prose embed references explicitly.

## Tool surfaces in the POC

The root `observastory-templates` directory belongs to the POC vault. Those small notes are the current internal Templater-facing command surface; they call reusable scripts housed in the `observastory-tools` package.
The root `ObservaStory` directory contains the POC workspaces and lenses. Neither folder belongs to the configured book or managed story-content roots.
